# wiki-ingest

입력은 원문 한 건 또는 사용자가 지정한 묶음이다. 결과는 근거·관계·적용 범위가 있는 위키 변경안이다. SCHEMA.md와 index를 읽는다. 기간 전체의 최신화는 [wiki-update](../wiki-update/SKILL.md)가 조사와 질문 묶음을 맡는다.

wiki.toml에서 위키 위치(wiki.path)·작업 공간(wiki.state)·원천·검토자를 확인하고, 해당 위키의 SCHEMA.md를 기준으로 작업한다. 경로 예시의 llm-wiki·.llm-wiki는 설정값으로 바꾼다.

## 1. 원천과 기존 지식 대조

원문을 줄 번호로 읽고, 이미 인용됐는지 `company-wiki registry --source <경로>`로, 검토 대기 중인지 `company-wiki review status`로 확인한다. 문서 원본이 있으면 렌더 사본보다 우선한다. 세션은 같은 주제의 결정·이유를 묶어 읽고 결과 문서를 우선 근거로 삼는다. Slack·Jira·Notion·Confluence는 [원천 탐색](../wiki-update/references/sources.md)에 따라 내보낸 사본을 줄 인용한다. 개인 클리핑처럼 등록 원천이 아닌 자료는 원래 조직 원천을 찾아 그것을 근거로 삼고, 찾지 못하면 채택 판단 필요로 보고한다.

기존 페이지를 바꾸는 변경이면 `company-wiki registry --page <페이지>`로 그 페이지에 기대는 페이지를 확인하고, 함께 고칠 내용이 있는지 같은 변경안에서 검토한다.

기존 관련 페이지와 비교해 추가·보강·축소·반박·대체를 구분한다. 원문을 고치거나 모델 제안을 사용자 결정으로 취급하지 않는다.

## 2. 채택 지식만 골라 변경안 작성

초안 배치·카드 형식은 [공통 검토 계약](../wiki-review/references/workflow.md)을 따른다. 초안은 작업 공간에 두며 위키 폴더에 쓰지 않는다. 필요한 변경만 작성한다.

- 원문 요약 페이지를 만들지 않는다. 원문에서 조직이 채택한 개념은 concept, 대상의 정의·관계는 entity, 판단·행동 기준은 policy의 해당 문장 옆에 줄 인용으로 넣고 frontmatter sources에도 남긴다.
- 채택 여부가 불분명한 내용, 미해결 질문, 연구 과정, 외부 주장은 위키 변경안이 아니라 "채택 판단 필요" 또는 작업 관리 항목으로 보고한다.
- owner는 원문·사용자 발언으로 확인한 담당자를 쓴다. 모르면 판단 질문에 넣는다.
- related로 기존 페이지와 연결한다. 관계 종류가 판단에 중요하면 type과 evidence를 붙인다. 존재하지 않는 페이지에 링크하지 않는다.
- entities에 업무 데이터(고객 목록, 인사 정보, 수치 현황)를 복제하지 않는다. 정의와 안정적인 관계만 두고 원래 시스템을 가리킨다.
- 주장 차이는 시점·대상·적용 조건을 먼저 비교한다. 대체라면 기존 페이지를 고치고, 양립 불가능하면 contradicts 관계와 양쪽 근거를 담당자에게 묻는다.

## 3. 검토에 인계

**update에서 호출됐으면 초안·근거·판단 후보만 반환한다.** 별도 질문이나 반영을 하지 않는다. **단독 요청이면 지정된 묶음 전체를 준비한 뒤 [wiki-review](../wiki-review/SKILL.md)에 넘겨 검토·담당자 결정·반영까지 진행한다.**

전달 전 근거가 문장을 실제로 지지하는지, 계획과 성과를 혼동하지 않는지, 채택하지 않은 내용이 섞이지 않았는지 확인한다. preview 결과와 미확인 근거·채택 판단이 필요한 원문을 함께 보고한다. 초안 수를 반영 수로 보고하지 않는다.
