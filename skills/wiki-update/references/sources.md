# 원천 탐색

wiki.toml의 활성 sources마다 path·kind·include/exclude·project 범위를 읽는다. 등록하지 않은 개인 폴더로 조사를 확대하지 않는다. 등록 경로가 없거나 읽히지 않으면 미완료로 기록한다.

## 문서와 Git

현재 문서와 Git 변경 이력, 미커밋 결과물을 대조한다. Git 이력은 문서 변화와 결정 이유의 단서이며 커밋 메시지만으로 사용자 승인을 확정하지 않는다. 필요한 과거 본문은 커밋 ID와 경로를 기록하고, 파일 줄 인용이 필요하면 선택한 텍스트만 로컬 원천 사본으로 보존한다. 출처·커밋·원본 경로를 함께 남긴다. 원문 Markdown이 있으면 렌더 사본과 중복 수집하지 않는다. 이동은 내용 대조로 새 지식과 구분한다.

## 세션

Claude는 선택한 프로젝트 디렉터리, Codex는 session_meta의 cwd·세션 관계를 확인한다. 파일 생성일보다 메시지 시각으로 기간을 나누며 결정 전후 문맥과 최종 정정을 읽는다. 모델·도구·하위 에이전트 보고를 사용자 결정으로 세지 않는다.

`python3 -B scripts/dump_session.py <별칭 또는 경로> --start N --end M`로 역할과 원본 JSONL 줄을 확인한다. 탐색용 --max-chars를 사용했더라도 인용할 줄은 생략 없이 재확인한다. Codex event_msg와 response_item의 중복을 주의한다.

Hermes 등 다른 형식은 실제 저장 위치·스키마를 확인해 읽기 전용으로 조사한다. SQLite라면 읽기 전용 연결을 사용한다. 현재 검증 도구가 지원하지 않는 세션은 원본 ID와 한계를 보고하고 결과 문서를 우선 인용한다. 가짜 세션 별칭이나 승인 인용을 만들지 않는다.

## Slack·Jira·Notion·Confluence

조직의 업무 도구는 등록한 kind(slack·jira·notion·confluence)와 path로 다룬다. path는 그 시스템에서 내보낸 텍스트·Markdown을 두는 폴더다. 에이전트는 사용 가능한 커넥터·MCP·내보내기 기능으로 원문을 찾을 수 있지만, 근거로 인용하는 것은 등록 폴더의 사본이다. 사본에는 인용에 필요한 내용만 두고 원본 URL·ID(채널·이슈 키·페이지 ID)·원본 수정 시각·내보낸 시각을 머리에 남긴다. 원본을 고치거나 전체를 일괄 복사하지 않는다.

registry는 사본의 변화만 감지한다. update는 인용 중인 사본을 원본의 현재 내용과 다시 대조하고, 바뀌었으면 사본을 새로 내보낸 뒤 changed·moved 인용을 재검토한다. 접근할 수 없으면 사본을 그대로 두고 미확인으로 기록한다. 커넥터가 없으면 설치를 가정하지 말고 접근 상태를 기록한다.

## 코드

kind code는 저장소 경로를 등록하고 파일 줄을 인용한다. 코드는 동작·구조의 근거이지 조직이 채택한 기준의 근거가 아니다. 정책은 채택을 보여주는 문서·결정과 함께 인용한다.

## 메모리·이슈

등록한 Claude mem·기타 메모리·이슈 추적 기록은 결정과 문서를 찾는 단서로 사용한다. 에이전트 요약을 사람 승인으로 대체하지 않는다. 사용하는 저장소의 이슈·댓글·기억을 종료 여부와 관계없이 기간 전체로 대조한다. 도구가 없으면 설치를 가정하지 말고 접근 상태를 기록한다.

개인 웹 클리핑처럼 개인이 수집한 자료는 원천이 아니다. 그런 자료에서 단서를 얻었다면 조직 원천에서 원문을 찾아 인용한다.
